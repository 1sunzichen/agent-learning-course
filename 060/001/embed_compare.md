# 关卡 3-7 · embedding 模型选型

> 面试必考：中文场景用什么 embedding、维度怎么选、API 还是本地。核心就一句话——**中文优先选国产开源（bge/m3e），省钱选本地，追效果加 reranker**。

---

## 一、主流模型一张表（中文视角）

| 模型 | 维度 | 中文效果 | 成本 | 部署 | 一句话定位 |
|---|---|---|---|---|---|
| text-embedding-ada-002 (OpenAI) | 1536 | 一般 | API 按 token 收费 | 云端 | 老一代，中文是短板 |
| text-embedding-3-small (OpenAI) | 1536→可降 512 | 中等 | 便宜 | 云端 | 便宜 + 可降维，通用首选 API |
| text-embedding-3-large (OpenAI) | 3072→可降 256 | 好 | 贵 | 云端 | 效果最好但烧钱 |
| bge-large-zh-v1.5 (BAAI) | 1024 | 中文专项 SOTA 级 | 免费 | 本地 GPU/CPU | 中文检索的标杆 |
| bge-m3 (BAAI) | 1024 | 多语言强 | 免费 | 本地 | 中英混合、多粒度、多功能 |
| m3e (moka-ai) | 768 | 中文好 | 免费 | 本地轻量 | 轻量中文，便宜够用 |
| paraphrase-multilingual-MiniLM-L12-v2 | 384 | 一般 | 免费 | 本地极轻 | 本课程 1-3 起一直在用的那个 |
| Qwen3-Embedding (阿里) | 可调 | 中文强 | 免费/API 都有 | 本地或云 | 新一代，MTEB 榜单靠前 |

> 补充（国外多语言）：Cohere embed-v3（可降维）、Jina embeddings v3（多语言+可降维）、Voyage-3 等，中文场景不如 bge 系性价比高，知道名字即可。

---

## 二、三个核心决策维度

### 1. 中文效果（最容易被忽略的坑）

用 OpenAI 的 ada-002 做中文检索，效果明显不如 bge——因为它的训练语料以英文为主。**结论：中文任务优先 bge-large-zh / bge-m3 / m3e，别无脑上 OpenAI。** 英文为主或中英混合，再用 3-small / bge-m3。

### 2. 维度 vs 成本（维度的本质）

- 维度越高，向量携带的语义信息越细，但**存储、内存、检索计算量都线性增长**。
- 维度是「精度」和「成本」的旋钮：768 维够用就别上 3072 维。
- **Matryoshka（套娃）降维**：3-small/3-large 支持把向量直接截断到 512/256 维，精度损失很小、成本大幅下降。面试能讲出这个词是加分项。

### 3. API vs 本地

| | API（OpenAI/云端） | 本地（bge/m3e） |
|---|---|---|
| 成本 | 按 token 计费，长期量大很贵 | 免费，一次性吃显存/内存 |
| 运维 | 免运维 | 要自己部署、维护 |
| 延迟 | 网络往返有延迟 | 本地毫秒级 |
| 数据 | 文本出域（有合规顾虑） | 数据不出域，可离线 |
| 速率 | 有速率限制、会限流 | 无限制 |

---

## 三、选型决策树（拿到需求照着走）

1. **数据能不能出域 / 能不能联网？**
   - 不能（涉密、离线）→ 本地 bge/m3e
   - 能 → 问下一问

2. **主要语言是什么？**
   - 中文为主 → bge-large-zh / bge-m3（本地）或 Qwen3-Embedding API
   - 英文/多语言 → 3-small（便宜）/ 3-large（追效果）

3. **量级和成本敏感度？**
   - 量大、抠成本 → 本地 m3e 或 3-small + Matryoshka 降维
   - 小规模、要省事 → 云端 API

---

## 四、两条进阶思路（面试加分）

1. **检索 + 重排（reranker）两段式**：embedding 召回 top-50（快、粗），再用 bge-reranker 这类交叉编码器精排 top-5（慢、准）。因为「双塔 embedding」精度有限，靠 reranker 补最后一步。面试问「怎么提升检索精度」，这是标准答案。

2. **对称 vs 非对称检索**：query 短、doc 长（非对称），用 `query: ` 前缀 prompt 或专用 instruction 模型，效果更好。bge 系支持加前缀（如 `为这个句子生成表示以用于检索相关文章：`）。

---

## 五、面试标准答法（背下来）

「embedding 选型看三点：语言、成本、部署。中文任务优先 bge-large-zh 或 bge-m3，中文效果明显好于 OpenAI 的 ada-002；维度上 768~1024 够用，想要更高精度再上 3-large（3072），并且 3-small/3-large 支持 Matryoshka 降维到 512，精度损失小、成本大降；部署上数据不能出域就本地跑 bge/m3e，省事就云端 API。再进阶一点，检索精度不够就加 reranker 做两段式召回+精排。」
