## 这份文件要完成什么

按 Agent 角色检查工具白名单，再检查额外授权并记录结果。

## 这样做的优点

权限规则集中，拒绝原因可以追踪。

## 代价与局限

字典里的角色和布尔授权不是可信身份系统；需要阻止绕过检查直接调工具。

## 适合什么场景

演示最小权限、规划工具网关。

## 不适合直接照搬的场景

将调用方自报身份直接当作生产授权。

## 改一个条件，检验是否理解

用只读角色请求写工具，检查是否在工具执行前拒绝并记录。

如果当前文件有未实现位置，先预测应该怎样变化，补齐后再验证；不要把“能启动”当作“实现正确”。
