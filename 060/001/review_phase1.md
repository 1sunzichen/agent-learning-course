## 二、三条主线（把 19 关串成体系）

1. **一个 agent 的骨架（消息流闭环）**：user 输入 → LLM 决策 → 调工具 → 工具结果喂回 → 再决策 → 最终答案。1-2/1-4/1-10 反复在练这个循环。

2. **生产的四个必修**：流式（1-5）、防护（1-8）、可观测（1-9）、成本（1-12）。缺一个都不叫生产级。

3. **决策模式的两条路**：ReAct（1-1，边走边看）vs Plan-and-Execute（1-6，先想后做），加上 Reflection（1-7）兜底纠错。

## 三、面试高频题自测（30 秒内答上来）

1. **ReAct 和 Plan-and-Execute 的区别？**
   - ReAct 每步「想一步做一步」，适合环境多变、需要边走边看；Plan 先规划再执行，适合步骤明确的任务。Plan 的 token 更省（规划一次），但中途出错要 replan。

2. **工具调用为什么要四层防护？**
   - 重试扛偶发故障、超时防挂死、幂等防重复副作用、降级保证可用。这是 agent 稳定性的地基。

3. **tracing 和 logging 的区别？**
   - logging 记「事件」（散落的日志行），tracing 记「一次完整调用的链路」（父子嵌套的 span 树），能回答「这次请求为什么慢/错在哪一步」。

4. **长期记忆怎么排序？**
   - 三权重：recency（最近）、importance（重要性，LLM 打分）、relevance（相关性，embedding 相似度）。这是 Generative Agents 记忆流的来源。

5. **上下文超窗怎么办？**
   - 四种：截断、摘要、滑动窗口、RAG 召回。生产常组合：近期原文（滑动窗口）+ 远期摘要或向量库召回。

6. **怎么让 LLM 稳定吐 JSON？**
   - prompt 要求 → json.loads 校验重试 → JSON mode → 函数调用 → pydantic 校验。从「靠嘴说」到「靠协议约束」逐级变稳。

7. **prompt injection 为什么根治不了？**
   - 模型无法可靠区分「指令」和「数据」，攻击者的话和开发者的话在模型眼里是同一类输入。只能分层防御 + 工具最小权限 + 敏感操作人审。

8. **怎么省钱？**
   - 压 prompt、减工具定义、结果缓存、长对话摘要、简单任务用便宜模型。先会算 token，才能谈优化。
