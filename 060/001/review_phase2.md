## 二、四种架构（白板能画、口述能讲）

1. **层级式（Orchestrator + Workers）**：一个主 agent 拆任务、分派、汇总。控制流集中，适合「一个明确目标拆成多块」的任务（写报告、做调研）。
2. **流水线式（Pipeline）**：研究 → 写作 → 审核，单方向串联。数据流清晰，适合「有固定工序、上一步产出下一步输入」的任务（内容生产）。
3. **协作式（对话/辩论）**：多 agent 平级多轮对话，互相质疑补充直到一致。适合「需要多视角讨论、达成共识」的任务（方案评审）。
4. **竞争式（生成 + judge）**：多个 agent 独立出方案，judge 选最优。适合「答案不唯一、要择优」的任务（文案、创意、算法方案）。

**面试 30 秒**：先画四个框，各带一句适用场景，最后落到「怎么选」——任务可拆、目标单一 → 层级式；有固定工序 → 流水线；要多视角 → 协作；要择优 → 竞争。实际生产常混合（层级式外层 + 某个 worker 内部用竞争式）。

## 三、四大生产线（架构之外的地基）

| 线 | 关卡 | 核心 |
|---|---|---|
| 通信 | 2-5 / 2-12 / 2-13 | A2A 结构化协议、消息路由、黑板共享——agent 之间怎么「对话」 |
| 状态 | 2-6 | 共享 state + 锁，谁读谁写要清楚，防并发冲突 |
| 容错 | 2-7 / 2-8 / 2-14 | 单个失败隔离降级、限流防打爆、死锁循环检测 |
| 可观测 | 2-15 | 跨 agent 分布式 tracing，一条请求全链路可追踪 |

**面试 30 秒**：多 agent 的难点不在「怎么让 LLM 干活」，在「多个 agent 之间怎么协作、出问题怎么兜底」。通信（协议/路由/黑板）、状态（共享+锁）、容错（隔离/限流/死锁检测）、可观测（分布式 tracing）四条线缺一不可。

## 四、三大生产坑 + 四张收口牌

**三大坑（面试官最爱问「多 agent 落地最大的坑」）：**

1. **状态共享**：多个 agent 写同一份状态，谁来同步、谁先谁后、冲突怎么办（2-6，锁 + 明确读写顺序）。
2. **容错**：一个 agent 挂掉不能拖垮全局，要隔离 + 降级（2-7），还要防并发打爆 API（2-8）和死锁循环（2-14）。
3. **成本**：agent 越多 token 越烧，要按 agent 分摊记账、设预算止损（2-16）。

**四张收口牌（Phase 2 收尾的「生产级」标志）：**

- **成本**（2-16）：token 记账 → 按 agent 分摊 → 超预算止损。
- **人机**（2-17）：高风险动作（发信/改库/扣款）必须 HITL，不全自动。
- **评测**（2-18）：协作质量量化（完成率/效率/质量/成本），改一版代码知道变好还是变坏。
- **安全**（2-19）：最小权限 + 越权拒绝 + 敏感操作管理员门槛 + 审计留痕。

## 五、面试高频题自测（30 秒内答上来）

1. **四种架构分别是什么、怎么选？**
   - 层级（拆派汇，目标单一）、流水线（上一下一，固定工序）、协作（多轮辩论，要共识）、竞争（生成+judge，要择优）。选型看「任务能不能拆、有没有固定工序、要不要多视角、答案是否唯一」。

2. **层级式和流水线式的本质区别？**
   - 层级是「控制流」——主 agent 决定谁做什么、什么时候做；流水线是「数据流」——数据沿固定工序单向流动，前段产出就是后段输入。层级可并行（多个 worker 同时干），流水线是串行的。

3. **A2A 和 MCP 的区别？**
   - A2A 是 agent 和 agent 之间的协议（对等、结构化消息）；MCP 是 agent 和工具/资源之间的协议（主从、调用外部能力）。一个是「同事对话」，一个是「用工具」。

4. **多 agent 生产落地最大的三个坑？**
   - 状态共享（同步/冲突）、容错（单点失败/并发/死锁）、成本（token 失控）。各 30 秒：状态加锁+明确读写、容错隔离降级+限流+死锁检测、成本分摊记账+预算止损。

5. **成本怎么控？**
   - 先会算（每个 agent 的 token → 钱），再会管：按 agent 分摊记账，总预算设止损线，超了就停派。源头省钱同单 agent：压 prompt、缓存、摘要、便宜模型、减少 agent 间无意义往返。

6. **human-in-the-loop 什么时候必须？**
   - 不可逆或高风险的副作用动作：发信、扣款、删数据、改生产配置。原则：关键节点停下来等人确认，而不是全自动。HITL 是「安全」的兜底，和 prompt 层防御互为补充。

7. **多 agent 评测和单 agent 评测差在哪？**
   - 单 agent 看「答对没」（准确率）；多 agent 还要看「协作得怎么样」——任务完成率、共识效率（轮数）、产出质量、成本，多维度加权。只测单个 worker 不够，协作过程本身会引入新的失败模式。

8. **多 agent 安全怎么做？**
   - 最小权限（每个 agent 只给够用的工具白名单）→ 调用前权限门（越权拒绝）→ 敏感操作额外门槛（delete/grant 仅管理员）→ 全程审计留痕。本质：不信任任何单个 agent，在架构层兜底。

9. **死锁 / 无限循环怎么检测？**
   - 死锁：agent 互相等待对方结果 → 超时 + 依赖图检测成环；循环：加轮数上限、检测重复状态（消息去重/哈希）触发打断。

10. **黑板模式和消息路由的区别？**
    - 黑板：广播式共享，谁都能读、按需取（适合松耦合协作）；消息路由：定向投递，有明确收发方（适合严格分工）。黑板灵活但难追踪，路由清晰但耦合高。
