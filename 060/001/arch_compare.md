# Phase 2 关卡 2-9 · 架构选型实战（白板对比）

> 面试必考：四种 Multi-Agent 架构分别是什么、怎么选。这一关不看代码，看你能不能画出图、讲清区别。

---

## 一、四种架构一张表

| 架构 | 本质 | 控制流 | 一句话 | 适合场景 | 典型坑 |
|---|---|---|---|---|---|
| 层级式 | 主 agent 拆任务、分派、汇总 | 上下（1 主 N 工） | 领导派活，手下干活 | 任务可拆、子任务独立 | orchestrator 单点，拆错全错 |
| 流水线式 | agent 串联，上输出是下输入 | 单向数据流 | 工厂流水线 | 有固定工序（研究→写作→审核） | 一断全断，不能并行 |
| 协作式 | 多 agent 对话辩论到一致 | 双向对话 | 圆桌讨论 | 开放式、需多角度（方案评审） | 轮数不可控、成本高、可能死循环 |
| 竞争式 | 多 agent 生成 + judge 选优 | 并行生成 + 评判 | 海选打分 | 答案有客观好坏（写文案/解题） | 成本 N+1 倍 |

---

## 二、选型决策树（面试 30 秒能讲）

拿到一个多 agent 任务，依次问三个问题：

1. **任务能不能拆成互不依赖的子任务？**
   - 能 → 层级式（orchestrator 拆 + worker 并行干 + 汇总）
   - 不能（有先后依赖）→ 问第二个

2. **依赖关系是不是固定的线性工序？**
   - 是（研究→写作→审核这种）→ 流水线式
   - 不是（需要来回讨论、互相修正）→ 问第三个

3. **是要「达成共识」还是「选出最优」？**
   - 达成共识（方案评审、头脑风暴）→ 协作式
   - 选出最优（写 slogan、解题，答案有客观好坏）→ 竞争式

---

## 三、两个易混点的本质区别（面试常问）

1. **层级式 vs 流水线式**：
   层级式是「控制流」——主 agent 决定"谁干什么"，worker 之间不传数据，都回报给主 agent；
   流水线式是「数据流」——结果从上一个流到下一个，没有中央调度者。
   一句话：层级式看「谁在指挥」，流水线看「数据往哪流」。

2. **协作式 vs 竞争式**：
   协作式是「一起讨论」——多个 agent 互相看对方的输出，迭代到一致；
   竞争式是「各做各的」——多个 agent 独立生成，互不看对方，最后由 judge 挑最好的。
   一句话：协作式「商量」，竞争式「海选」。

## 四、实战场景匹配（对着你的项目练）

| 场景 | 选什么 | 为什么 |
|---|---|---|
| 张帝秋招定级器（一批企业按规则打分排序） | 层级式 | 企业互不依赖可并行评估，权重规则集中在顶层 |
| 写一篇带引用的深度报告 | 流水线式 | 检索→写作→审核是固定工序 |
| 微服务 vs 单体 技术选型评审 | 协作式 | 需要多角度辩论到一致 |
| 给咖啡店写 10 条 slogan 选 1 条 | 竞争式 | 答案有客观好坏，judge 选优 |

---

## 五、面试标准答法（背下来）

「Multi-Agent 有四种架构：层级式是主 agent 拆任务分派汇总，适合任务可拆、子任务独立；流水线式是 agent 串联、上输出是下输入，适合固定工序；协作式是多 agent 对话辩论到一致，适合开放式问题；竞争式是多 agent 独立生成加 judge 选优，适合答案有客观好坏的场景。

选型看三点：能不能拆（能→层级）、依赖是不是线性（是→流水线）、要共识还是要最优（共识→协作、最优→竞争）。层级式是控制流，流水线式是数据流，这是两者本质区别。」
